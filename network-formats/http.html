HTTP/1.1 Message

HTTP/1.1 요청·응답의 시작 줄, 헤더와 본문 및 주요 메서드·상태 코드입니다.

APPLICATION LAYER

HTTP/1.1 메시지 형식

텍스트 형식 · 고정 비트 폭 없음
필드 이름과 역할
필드풀네임크기설명
Request LineRequest Line가변 길이Method, 공백, Request Target, 공백, HTTP Version, CRLF 순서입니다.
MethodRequest Method가변 길이요청할 동작을 나타내는 토큰입니다.
  • GET — 표현 조회
  • HEAD — GET에 대응하는 헤더를 조회하되 응답 본문 없음; 본문 생성 중에만 결정되는 헤더는 생략 가능
  • POST — 리소스별 처리 요청
  • PUT — 표현 생성 또는 교체
  • DELETE — 리소스 연결 제거 요청
  • CONNECT — 터널 설정
  • OPTIONS — 통신 옵션 조회
  • PATCH — 부분 수정
Request TargetRequest Target가변 길이요청 대상을 나타냅니다. 경로·질의, 절대 URI, CONNECT의 호스트:포트, OPTIONS의 * 등이 사용됩니다.
HTTP VersionHTTP VersionHTTP/1.1 토큰: 8 B · 64 bits여기서는 HTTP/1.1의 텍스트 메시지를 표시합니다. HTTP/2와 HTTP/3는 다른 바이너리 프레임 형식을 사용합니다.
Status LineStatus Line가변 길이HTTP Version, 공백, Status Code, 공백, 선택적인 Reason Phrase, CRLF 순서입니다.
Status CodeStatus Code3 B · 24 bits세 자리 십진수로 응답 결과를 나타냅니다.
  • 200 — OK
  • 201 — Created
  • 204 — No Content
  • 301 — Moved Permanently
  • 302 — Found
  • 304 — Not Modified
  • 400 — Bad Request
  • 401 — Unauthorized
  • 403 — Forbidden
  • 404 — Not Found
  • 405 — Method Not Allowed
  • 429 — Too Many Requests
  • 500 — Internal Server Error
  • 502 — Bad Gateway
  • 503 — Service Unavailable
Reason PhraseReason Phrase가변 길이상태 코드 뒤의 선택적 설명입니다. 클라이언트는 상태 코드를 기준으로 처리합니다.
Header FieldsHeader Fields가변 길이Field Name, 콜론, 선택적 공백, Field Value, 선택적 공백과 CRLF로 구성됩니다. HTTP/1.1 요청에는 Host 필드가 필수입니다.
  • Host — 요청 대상 호스트와 선택적인 포트
  • Content-Type — 본문의 미디어 유형
  • Content-Length — 일반적으로 본문 길이(바이트); HEAD·304에서는 대응하는 표현의 길이를 나타낼 수 있음
  • Date — 메시지 생성 시각
  • Transfer-Encoding — 전송 코딩; chunked 등
  • Accept — 허용할 응답 미디어 유형
  • Authorization — 인증 정보
  • Cache-Control — 캐시 지시
  • Location — 리다이렉션 등 대상 URI
CRLFCarriage Return and Line Feed2 B · 16 bits시작 줄과 각 헤더 줄의 끝입니다. CR(0x0D)과 LF(0x0A) 두 바이트입니다.
Empty LineHeader Section Terminator2 B · 16 bits빈 CRLF 줄이 헤더 영역을 종료합니다.
Message BodyMessage Body가변 길이메시지의 본문입니다. 길이는 RFC9112의 우선순위 규칙으로 결정하며, 일부 응답은 연결 종료로 끝납니다. HEAD 응답과 1xx·204·304 응답에는 본문이 없습니다. CONNECT의 2xx 응답 뒤에는 터널 데이터가 이어집니다. chunked 전송에는 청크 크기·종료 청크와 선택적 트레일러가 포함됩니다.

응답 예시는 Content-Length: 13으로 본문 길이를 지정합니다. 요청 예시는 Content-Length와 Transfer-Encoding이 없으므로 본문 길이가 0입니다. 본문은 임의의 바이트열이며 줄 끝을 CRLF로 제한하지 않습니다. chunked 형식은 별도의 청크 구조를 사용합니다.
